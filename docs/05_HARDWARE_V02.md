# v0.2 真实相机与 IMU 接入

## Quick Start

本版开发中，继续在 `codex/vins-platform`，从已验收的 `vins-platform-v0.1.0` 演进。当前可用接口仍以第 03 份指南为准，下面的 sensor/record 流程将在真实硬件验收后标为可用

目标流程为复制一份根目录模板、确认现场标定与设备参数，然后 `./vins -c field.yaml run`。只采集时使用同入口的 record；status、stop、pull、remote 复用 v0.1。板端不安装 ROS、Python 包、厂商 SDK 或驱动用户态程序

## 本轮范围

- 相机：FLIR Blackfly S BFS-U3-31S4M-BD，序列号 25162247，Spinnaker 3.1.0.79 ARM64
- IMU：`/dev/ttyS7`，115200，55 d1 00 02／54 字节校验帧。保留驱动标称 200 参数，实际约 100 Hz；不改硬件、不伪造频率或同步
- 主机交叉编译适配器，第三方 SDK 只做私有提取和打包；不借用板端 /opt/ros、/opt/spinnaker 或旧 devel 前缀完成正式验收
- 原始图像、设备/接收时间信息与 IMU 数据留存；裁剪、缩放及格式转换明确属于 VINS 下游输入，不能用处理后图像冒充原始像素
- 不新增 v0.3 的一整套硬件监控，不改算法求解器，不构建回环

用户于本轮确认：相机/IMU 安装未变，可以配合运动验证。历史现场标定是待验证初值，不因同一安装就声明精度合格；需要先核对图像尺寸、ROI、缩放和单色编码是否与标定一致

## 分阶段提交与回退点

1. 来源与接入约定：记录旧驱动、SDK、现场参数及校验值，保持 v0.1 tag 不变
2. 驱动与 SDK：可见 third_party 目录、版本/SHA256、最小 C++ 适配器及本机交叉编译；协议边界与退出有必要测试
3. 任务联动：同一配置扩展 sensor/record，复用任务所有权、摘要、停止、归档和回收；保留 replay 回归
4. 真机验收：私有包静态收数 → 用户运动时 VINS 初始化和位姿 → 正常停止 → 原始 bag 与轨迹回收 → 同段数据离线重放

每步完成独立 commit，失败证据保留；仅全部验收后打新的 annotated 版本 tag。SDK、下载源码、构建、运行数据 Git 忽略，锁、适配器、补丁、脚本、文档和小型证据纳入 Git；不把板端变成源码开发仓库

## 验收和证据边界

检查真实设备身份、图像尺寸/格式、IMU 有限值及时间、实际消息率；确认 ROS 观察、录包消息和 VINS 输出分别有证据。停止必须关闭设备、结束录包并校验文件，不只看到节点存活就判成功

实采无真值时只说明软件链和回放一致性，不能声明绝对精度。主机收到/解析时间与相机设备时钟分别记录，软件时间映射不称硬件同步。运动不足、缺有效标定或设备故障时明确记录未通过项，不降低初始化或轨迹验收标准

## 来源约束

厂商 ARM64 deb 优先从主机已验证缓存读取；本机缺少时可从已授权板上已有归档只读回收，并逐文件 SHA256 核验。重新 clone 后也可把相同厂商归档放入提示的 cache/archives，不依赖板端已安装前缀，也不运行 deb 安装脚本

旧 GNW 源码许可字段含糊，旧相机包含固定 ROI 和 Bayer 转换；只保留来源/哈希与协议线索，适配器按实际设备做最小实现，不把来源不明代码或厂商头文件直接提交到公开仓库

## 接入进度

已从旧 `p600/imu_mavros_cam.sh` 核实实际启动 `spinnaker_multi`：2×2 binning 得到 1024×768 Mono8，再中心裁剪 512×512（x=256、y=128），不是 resize 驱动的固定偏移 ROI。用户再次确认历史标定正是该 binning，且相机由 IMU 通过 Line0 硬触发；保留原内参及这一几何关系，不擅自改自由运行模式

最小相机/IMU 适配器已在主机以 GCC 9 交叉编译成功；GNW 协议的所有分包位置、噪声、校验错误恢复和连续帧测试通过 ASan/UBSan（当前沙箱不支持 LeakSanitizer，单独关闭泄漏检测）。此处只验收构建和协议边界，正式私有包收数仍待验证

相机 SDK 的 USB 运行库已经包含在锁定的 Focal sysroot 中，直接纳入私有包及其依赖闭包，无需另装板端 libusb。SDK 只用 `dpkg-deb -x` 提取，未执行安装脚本。后续包内显式设置 GenTL 插件路径并检查进程 maps，避免误用 `/opt/spinnaker`

静态第 1 轮缺最后一张处理图，保留为失败证据；原因与信号退出边界见 evidence/hardware-v02/static-001。最小退出修复后第 2 轮通过：原图/处理图/metadata 各409，IMU2101，所有进程退出0，无强制清理。主机再独立核对三者接收时间逐帧一致、设备帧号连续；完整失败与成功 bag 均保留在 experiments，尚未据此声明运动 VIO 或标定精度通过

用户配合的首轮运动采集已完成：1209组三路相机帧逐帧匹配、设备帧号连续，IMU6245；VINS初始化1次、轨迹257条、末帧差50ms，所有进程退出0。但运行中 maps 发现 GenApi 动态加载的 liblog4cpp 落到全局 /opt/spinnaker；该轮保留为“功能跑通、私有依赖验收失败”，不据此发布版本。打包器补齐厂商辅助 .so 后仍须重新检查实际 maps

现场 IMU 触发器独立于串口读取工作。任务启动顺序进一步固定为先使录包器就绪、串口清空启动前旧缓冲并获得第一条 IMU，再接受相机图像，避免图像时间早于本次 IMU 覆盖；不向 IMU 发送改频或触发配置命令

## SDK 首次准备

`./vins build/run/record` 优先复用 cache/archives 的三个锁定归档；缺失时用当前配置的 SSH 身份从已知板上原始归档目录只读回收，再核对 SHA256。不会从已安装 `/opt/spinnaker` 抽取库，也不执行安装脚本

如更换为没有原始归档的板子，应从 [FLIR 官方 SDK 页面](https://www.teledynevisionsolutions.com/products/spinnaker-sdk/) 获得同版本 ARM64 包，将 `libspinnaker_3.1.0.79_arm64.deb`、`libspinnaker-dev_3.1.0.79_arm64.deb`、`libgentl_3.1.0.79_arm64.deb` 放到 cache/archives 后重试。精确校验值与本次种子路径在 buildkit/spinnaker.lock.json
